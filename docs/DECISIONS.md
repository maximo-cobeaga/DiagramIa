# Registro de decisiones

| ADR | Decisión | Motivo y límites |
|---|---|---|
| 001 | Diagramia; nombre uniforme ES/EN | Marca descriptiva; verificación legal/comercial pendiente |
| 002 | Monorepo TypeScript con npm workspaces | Contratos compartidos sin depender de servicios para comenzar |
| 003 | SVG propio en starter | Editabilidad/exportación exacta; medir performance antes de motor alternativo |
| 004 | JSON versionado + acciones controladas | Humanos y agentes modifican la misma representación |
| 005 | Zod + JSON Schema generado | Runtime tipado y contrato para IAs; semántica adicional en engine |
| 006 | Preview aislado + commit atómico | Observabilidad sin dejar un documento parcialmente modificado |
| 007 | LocalStorage y archivo MCP separados al inicio | Arranque sin backend; sincronización obligatoria en P5 |
| 008 | MCP SDK oficial v2 fijado | API actual comprobada; no mezclar ejemplos v1 y v2 |
| 009 | Backend TS/Fastify + PostgreSQL + S3 en fases SaaS | Reutilizar core, CAS y control de assets; todavía no implementado |
| 010 | Higgsfield como adapter opcional | No bloquear el editor ni prometer capacidades/API no verificadas |
| 011 | Historial y timeline separados | Deshacer cambios no altera el tiempo de una presentación |
| 012 | No colaboración CRDT en primer corte | Primero estabilidad de documentos y transporte; colaboración después |

Nuevos ADR: contexto → alternativas → decisión → consecuencias → pruebas/migración necesarias. No reabrir decisiones sin evidencia o nueva instrucción del usuario.

Si hiciera falta lógica condicional real, se agrega encima sin romper esto |
| 021 | Imágenes embebidas en el documento como base64, máx. 400 KB y 40 por documento | No hay storage hasta P4.3. Formato verificado por firma; SVG sólo estático (sin script, eventos, embebidos ni referencias externas) y siempre dibujado con `<image>`. Un asset existe mientras un nodo lo use; el ledger guarda su huella, no el archivo. El contexto para IA describe las imágenes sin enviar su contenido |

| 024 | Vista previa de propuestas como copia de staging en el estado de vista | El canvas dibuja la copia con lo agregado/modificado resaltado y queda de sólo lectura; el documento no cambia hasta aceptar. Paso a paso = aplicar los primeros N pasos sobre la copia |
| 025 | El placement relativo hereda la zona del nodo de referencia | `below/above/rightOf/leftOf` sin `inside`: si el resultado cabe en la zona del nodo vecino, el nuevo nodo pertenece a ella. Evita nodos visualmente dentro de una zona pero sin pertenencia. Surgió del smoke con un modelo real |
| 026 | Modo JSON nativo en el adapter compatible y normalización de `null` | Reduce respuestas inválidas de modelos chicos sin relajar la validación del engine. Reparaciones configurables (`DIAGRAMIA_MAX_REPAIRS`, 1 por defecto, máx. 3) |
| 019 | Smoke de navegador por protocolo DevTools con Chrome/Edge ya instalados, sin dependencias | Da evidencia real de interacción sin sumar Playwright. No reemplaza la revisión manual ni cubre lector de pantalla |

## ADR agregados en la continuación del 01/10/2026

| ADR | Decisión | Motivo y límites |
|---|---|---|
| 027 | Schema 1.3.0 separa el tipo semántico (`kind`) de la forma (`shape`), agrega estilos editables y enganches libres en los bordes | Responde a formas de flujo/UML y conectores flexibles sin convertir el diagrama en una imagen. Migración 1.2.0→1.3.0 conserva IDs, posición y aspecto anterior mediante valores por defecto; schemas y ejemplos se regeneran. Las rutas manuales, curvas y cruces entre conexiones aún pueden superponerse |
| 028 | `create` recibe un inventario de zonas, nodos y conexiones; el gateway lo convierte en acciones del core | Un modelo local de 7B inventaba tipos de acción y geometría al crear desde cero. El inventario reduce la salida que debe escribir y deja geometría y validación en el engine. El modelo sigue decidiendo contenido y relaciones; cada propuesta requiere revisión humana. El ordenador rechaza lotes que exceden 200 acciones en vez de perder correcciones silenciosamente |
| 029 | El layout reserva espacio según el ancho estimado de las etiquetas de conexiones | La comprobación estricta encontró etiquetas de flechas encima de nodos. Se usa la misma medida aproximada que el routing y se prueba con etiquetas largas; no garantiza ausencia de todos los cruces ni equivale a medición tipográfica del navegador |
| 030 | PostgreSQL de desarrollo en Compose con imagen oficial `postgres:17.11-alpine`, puerto sólo en loopback y volumen nombrado | P4.5 prepara P4.2 sin exponer la base a la red ni sumar una dependencia npm. Contraseña fija sólo como valor de desarrollo, configurable por entorno; nunca usarla en producción. Un smoke crea dos proyectos efímeros, restaura `pg_dump` en el segundo y comprueba una fila. El backend aún no usa la base. PostgreSQL usa su licencia permisiva oficial |
| 031 | Repositorio PostgreSQL con `pg` 8.23.1, migración con checksum y recibos fuera del documento | P4.2 necesita transacciones reales y CAS. Una fila bloqueada serializa writers, `UPDATE ... WHERE revision` comprueba la revisión, y versión/recibo/auditoría se guardan en la misma transacción. Los recibos duran más que los 100 IDs del core. Restaurar crea nueva revisión. `pg` es MIT; las rutas requieren un token sólo del servidor hasta que P4.1 provea identidad y scoping por proyecto. El editor no recibe ese token; P5.1 hará la conexión autorizada. |
| 032 | Interop draw.io XML y DOT por subconjuntos editables con reporte de pérdidas | P6.2 usa `saxes` 6.0.0 (ISC) para parsear XML estricto sin resolver recursos externos, rechaza DTD/entidades y limita tamaño/profundidad. Páginas draw.io comprimidas se desinflan con la API estándar `DecompressionStream` y límite de salida. DOT se analiza en código con límites; nunca se ejecuta Graphviz. Sólo JSON de Diagramia conserva el documento completo. |
| 033 | El inventario de Crear publica los `kind` exactos y normaliza sólo alias semánticos conocidos | Un modelo local devolvió tipos como `user` y `api` pese a que el core exige `actor` y `service`. El gateway traduce un mapa cerrado de alias en Crear y entrega al modelo la lista exacta en el prompt y en la reparación. Valores desconocidos siguen rechazados; el core conserva el contrato canónico y la propuesta no se aplica sin aceptación. |
| 034 | Schema 1.4.0 agrega trazos libres independientes de las conexiones | El usuario necesita líneas, flechas y dibujo a mano alzada que no exijan nodos como extremos. Se agregan dibujos con puntos y estilo al documento canónico, acciones atómicas de alta/edición/borrado y migración aditiva desde 1.3.0. Los IDs existentes se conservan; los dibujos se seleccionan, mueven, eliminan, encuadran y exportan como SVG junto con el resto. Interoperabilidad Mermaid/DOT/draw.io no representa estos trazos y debe informarlo si se implementa su exportación. |
| 035 | Schema 1.5.0 agrega pistas con clips ligados al ID de paso | P2.4 requiere varios efectos simultáneos sin duplicar el reloj ni los pasos. Se eligió una grilla por paso y tres tipos cerrados: resaltado, texto y cámara. La migración 1.4.0→1.5.0 agrega `tracks: []` y conserva todos los IDs. El engine valida referencias y un clip por paso en cada pista; al borrar nodos, conexiones, frames o pasos poda clips/referencias y devuelve advertencias. Escenarios filtran los clips por paso visible; el último clip de cámara de la lista prevalece. Export timeline JSON conserva la estructura; Markdown la describe. Aún no hay audio ni keyframes dentro de un paso. Tests core y smoke de navegador cubren migración, ramas, poda y edición. |

## Decisiones de producto recibidas para el MVP

`DiagramIa_Decisiones_MVP.md` define acceso de invitado a la pizarra, cuenta obligatoria para IA y nube, borrador local, topes de guardado y cuota inicial de IA a medir. Se conserva como guía para P4.1/P4.4. «GPT Luna» requiere identificar modelo/API y medir costo antes de elegir adapter. Google Drive queda fuera del MVP. Las cuentas y cuotas iniciales se implementaron en ADR 037–038; todavía no se activaron cobros reales.

## ADR agregados en el avance del MVP (01/10/2026)

| ADR | Decisión | Motivo y límites |
|---|---|---|
| 036 | Canal compartido por API y PostgreSQL con CAS, recibos y polling; MCP stdio usa token de servidor | P5.1 une editor y MCP sin dar el token al navegador. El editor envía lotes de acciones canónicas en orden, consulta revisiones y reconecta comparando el contenido local. Un conflicto conserva la copia local y ofrece descargarla; undo/redo compartido crea una nueva revisión mediante restore. El espacio sin cuenta sólo se habilita en loopback con `DIAGRAMIA_LOCAL_WORKSPACE=1`. Polling de 2,5 s evita un protocolo nuevo en este corte; P5.2 deberá sumar transporte remoto autorizado por usuario. |
| 037 | Auth0 Universal Login como proveedor inicial, integrado por OIDC Authorization Code + PKCE con `openid-client` 6.8.8 | No se desarrolla un sistema de contraseñas. Issuer, cliente y callback se configuran sólo en servidor; state, nonce, cookie de flujo y firma del ID Token se verifican antes de crear una sesión opaca con hash en PostgreSQL. El backend admite otro issuer compatible. Se probó con issuer firmado local; Auth0 real y seguridad de despliegue siguen pendientes. `openid-client` es MIT. |
| 038 | IDs semánticos del documento separados del ID opaco de almacenamiento; proyecto privado por cuenta y cuotas transaccionales | Dos cuentas pueden subir el mismo ejemplo sin colisión ni lectura cruzada. La migración 002 agrega usuarios, proyectos, membresías, sesiones y vínculo proyecto-documento; las rutas de nube autorizan por sesión/proyecto y devuelven 404 fuera del proyecto. Free limita a 3 documentos, 10 MB por documento con versiones y 30 MB por proyecto. Créditos IA: 20 al mes, 6 al día; Crear consume 2 y otros modos 1, con reserva y recibo idempotente antes del proveedor. Son valores iniciales para medir, no precios ni garantía económica de publicación; Pro/BYOK/billing siguen pendientes. |
| 039 | PDF visual con `pdf-lib` 1.17.1 y rasterización del SVG del editor | P6.4 necesita un PDF sin volver a modelar formas en otro motor. A4 vertical u horizontal según contenido, imagen ajustada al área, fondo blanco y hasta 100 páginas/4096 px por página. La presentación exporta cada paso visible con escenario, encuadre, resaltado y texto; no codifica tiempo ni movimiento. El PDF no es editable y no sustituye el JSON. `pdf-lib` es MIT; falta una revisión manual de PDFs complejos y un artefacto temporal. |
| 040 | Conservar `node:http` en el gateway durante P4/P5.1; posponer Fastify de ADR 009/016 | El servidor actual ya aplica rutas, validación, CORS, cookies y errores de manera comprobada; introducir Fastify sólo para estas rutas no aporta una capacidad necesaria y agregaría una migración simultánea a identidad y sync. Se mantiene PostgreSQL; el almacenamiento de assets S3 sigue pendiente de P4.3. Reconsiderar framework al crecer rutas/jobs o al preparar el despliegue. |
| 041 | P6.3 usa importadores/exportadores locales de subconjuntos PlantUML y BPMN, sin ejecutar motores externos | El documento canónico sigue en core y los formatos ajenos no reemplazan su modelo. PlantUML acepta clases, secuencia y estados simples; ninguna macro/include/directiva se ejecuta. BPMN acepta el primer proceso con eventos, tareas, gateways y flujos; rechaza un flujo hacia elemento omitido para no romper referencias y no simula semántica ejecutable. `saxes` existente analiza XML con límite, namespace y DTD/entidades prohibidos. BPMN DI se conserva si está completo; de otro modo se calcula layout. Export BPMN marca `isExecutable=false`; gateways paralelos se dibujan como hexágonos para conservar su distinción semántica en el round-trip. Pérdidas se informan; JSON queda como único formato sin pérdidas. No se agrega dependencia nueva. |
| 042 | MCP remoto se monta en el gateway como recurso OAuth Streamable HTTP con autorización por usuario/proyecto | `@modelcontextprotocol/server` 2.2.0 y `@modelcontextprotocol/node` 2.1.0 (MIT) proveen el transporte y desafío de scopes; `jose` 6.2.12 (MIT) verifica access tokens RS256 con JWKS, issuer, audience exacta y vencimiento. La cuenta debe existir por OIDC; no se crea una cuenta a partir de un access token. `diagramia:read` abre la conexión y `diagramia:write` autoriza `apply_actions`; el rol viewer revoca escritura. El repositorio limita cada documento por project ID. Host/Origin públicos se validan; HTTP sólo en loopback. El modo stdio conserva su contrato. La prueba local usa issuer falso firmado y cliente MCP real; falta validar Auth0/hosts/proxy reales antes de publicar. |
